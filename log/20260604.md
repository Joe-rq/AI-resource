## [ingest] Thin Harness, Fat Skills（套具要瘦，技能要胖） (2 pages created, 1 index updated, 1 log appended)

**Source**: `D:\03resource\_Projects\work\harness-lab\context\references\2026-04-18-thin-harness-fat-skills.md`（来源标注："我读 Claude Code 源码 51.2 万行"——指 Anthropic 2026-03-31 误发 npm registry 事件）

**主题**: AI 编码 agent 的 10x–1000x 生产力差距不来自模型智能（2x 的人和 100x 的人用同样的模型），而来自**套具架构**。一句话原则：**Thin Harness, Fat Skills**——把智能向上推到 markdown 流程文件（skill），把执行向下推给确定性工具，把中间层（harness）保持极薄。

**五个核心定义**：
1. **Skill 文件** — 可复用 markdown 文档，教"怎么做"；**Skill 是一种方法调用**（同过程 + 不同参数 = 完全不同能力；`/investigate` 例：传 (安全科学家, 沉默了吗, 210 万封邮件) 产医学分析师；传 (空壳公司, 协调捐款了吗, FEC 申报) 产取证调查员）
2. **Harness** — 只做四件事：跑循环 / 读写文件 / 管理上下文 / 强制安全；~200 行；75x 速度差 vs fat harness
3. **Resolver** — 上下文路由表（"任务 X 出现时先加载文档 Y"）；Claude Code 的 skill `description` 字段就是内置 resolver；20,000 行 CLAUDE.md → 200 行指针的自白
4. **Latent vs. Deterministic** — 把错的工作放到错的一侧是反模式；800 人座位图 = 确定性组合优化被错塞进 latent space
5. **Diarization** — 模型读尽资料输出一页判断；SQL/RAG 做不到；嵌入相似度搜索做不到

**三层架构**（mermaid 图）：
- 顶：Fat Skills（90% 价值，markdown 流程）
- 中：Thin Harness（~200 LOC，JSON in text out）
- 底：Deterministic 应用层（SQL、文件、CLI）

**单向原则**：`intelligence ↑` / `execution ↓` / `harness_LOC ≈ 200`；模型升级自动惠及所有 skill，确定性层保持完美可靠。

**Self-rewriting skill 循环**（YC Startup School 案例）：
- `/enrich-founder`：拉取所有来源 → diarize → 标出 founder "嘴上说的" vs "实际在做的" gap
- `/match-*`：同一 skill 三次调用、三套策略（breakout 1200/30/room / lunch 600/8/table 跨 sector / live 200ms 1:1）
- `/improve`：读 NPS → diarize "OK" 评级 → 写回 matching skill 文件
- 实证：7 月 12% "OK" → 下次 4%（8pp 提升、**0 行代码改写**）

**零一次性工作纪律**：
> "你不被允许做一次性工作。如果我让你做某件事，而它属于'还会再做一次'的类型，你必须：手动在 3–10 个样本上做一遍、给我看输出、我批准后**编纂成 skill 文件**、自动化的挂 cron。**测试：如果我必须第二次向你请求，你失败了。**"

## [ingest] Hermes Agent 之后：AI 开发需要一层治理协议（张晨曦 / wow-harness v3 设计者一手分享） (1 summary created, 5 ref pointers created, 1 index updated, 1 log appended)

**Source**: `D:\03resource\_Projects\work\harness-lab\context\references\2026-05-20-hermes-agent-harness.md`（微信公众号，2026-05-20，张晨曦 Nature 撰写的 wow-harness v3 技术分享）

**主题**: 现有 AI 开发工具（Claude Code、Superpowers、Hermes Agent、OpenHands）都只优化"一个人 + 一个 agent"的单次体验，**没有任何一套工具在管"一百次 session 之间不漂移"**。wow-harness v3 的设计者本人撰写的一手分享，覆盖 v3 骨架（事件溯源、概念演化、双层验证、自动扩张任务图）。

**核心判断**：
> 协议比能力重要，治理比智能重要，长期连贯性比单次质量重要。

**v3 五个核心问题及方案**：
1. **AI 做过的事怎么不丢** — 事件时间线（只追加、不可篡改）+ 增量状态推导 + 快照压缩
2. **工程概念跨 session 怎么不漂移** — 概念节点生命周期（创建 → 修改 → 被替换 → 退役）+ 新颖性检查
3. **怎么确保 AI 产出真的做完了** — 双层验证：自检（物理拦截）+ 交叉验证（schema 级无写权限）
4. **怎么让 AI 成为自运转组织** — 自动扩张任务图 + 事件触发 agent spawn + 上下文胶囊
5. **项目负责人怎么不退化判断权** — 工程决策 AI 自做，语义判断升级到人（产品语言描述）

**与现有工具的根本区别**：
- Claude Code = v3 的地基（单次 session 高效执行），v3 加跨 session 组织级治理
- Superpowers = 把 agent 当需要管教的执行者（prompt 层行为约束），v3 让 agent 从系统理解推导行为
- Hermes Agent = 一个人的助手（单用户单 agent），v3 假设多 agent 并行
- OpenHands = EventStream 是 session 内临时消息总线，v3 事件时间线是永久的

**学术验证**：与 [[entities/ESAA|ESAA]] 论文（arxiv 2602.23193）核心命题高度重合（意图与执行分离 / 长期一致性 / 状态漂移），v3 在多个维度超出论文范围（概念节点生命周期状态机、约束规则独立生命周期、上下文胶囊机制、三正交审查方法论、闭合合约驱动修复协议）。
