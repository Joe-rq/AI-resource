## 厨房类比

MCP 提供了专业厨房：访问工具、食材和设备。  
技能则提供食谱：创建有价值事物的分步说明。  

两者结合，使用户能够完成复杂任务，而无需自己弄清楚每一步。

它们如何协同工作：

| MCP（连接性） | 技能（知识） |
| --- | --- |
| 将 Claude 连接到您的服务（Notion、Asana、Linear 等） | 教会 Claude 如何有效使用您的服务 |
| 提供实时数据访问和工具调用 | 捕捉工作流程和最佳实践 |
| Claude 能做什么 | Claude 应该如何做 |

# 为什么这对您的 MCP 用户很重要

## 没有技能的情况：

• 用户连接了您的 MCP，但不知道下一步该做什么  
• 支持工单询问“如何使用您的集成完成 X？”  
• 每次对话都从零开始  
• 结果不一致，因为用户每次的提示方式不同  
• 当真正问题在于工作流程指导时，用户却归咎于您的连接器  

## 有技能的情况：

• 预构建的工作流在需要时自动激活 • 一致、可靠的工具使用 • 最佳实践嵌入到每一次交互中 • 降低您的集成学习曲线 <!-- page break -->

## 关键规则

name (必需): SKILL.md 命名规范：
• 仅使用 kebabcase（短横线连接）
• 必须恰好为 SKILL.md（区分大小写）
• 无空格或大写字母
• 不接受任何变体（SKILL.MD, skill.md 等）
• 应与文件夹名称匹配

Skill 文件夹命名：
description (必需):
• 使用 kebabcase：notionprojectsetup ✅
• 必须包含两者：
  – 技能做什么
  – 何时使用（触发条件）
• 无空格：Notion Project Setup ❌
• 无下划线：notion_project_setup ❌
• 少于 1024 个字符
• 无大写字母：NotionProjectSetup ❌
• 无 XML 标签（< 或 >）

No README.md:
• 包含用户可能提及的具体任务
• 不要在技能文件夹内包含 README.md
• 如果相关，请提及文件类型
• 所有文档应放在 SKILL.md 或 references/ 中
